# Feature: What's New（新功能通知）

## 问题背景

WFE 系统不断迭代更新，新增功能和改进。目前存在以下问题：

**当前问题：**

- 用户不知道系统有哪些新功能
- 重要更新容易被用户忽略
- 没有统一的渠道通知用户系统变化
- 用户培训成本高，需要单独通知每个用户

**核心痛点：**

- 新功能上线后用户不知道怎么使用
- 无法追踪用户是否已阅读更新内容
- 缺乏管理员维护更新内容的后台

---

## 解决方案

1. **用户端**：在页面右上角用户头像旁边添加通知图标，有未读更新时显示红点提示。点击后展开更新列表，用户可查看详情。

2. **管理端**：提供 System Admin 专属的管理页面，可创建、编辑、删除更新内容，支持富文本编辑和定时发布。

---

## 设计原则

1. **非侵入式** — 通知图标不打断用户工作流，用户主动点击查看
2. **已读追踪** — 记录用户已读状态，只提示未读内容
3. **权限分离** — 仅 System Admin 可管理内容，普通用户只能查看
4. **时间排序** — 按发布时间倒序显示，最新内容在最前

---

## 功能设计

### 一、用户端 - 通知图标与面板

#### 1.1 通知图标

在页面右上角，用户头像**左侧**添加通知图标：

- **图标样式**：铃铛图标（或感叹号/公告图标）
- **未读提示**：有未读更新时，图标右上角显示红色小圆点
- **数字徽章**：未读数量 > 0 时显示数字（最大显示 9+）

#### 1.2 通知面板

点击通知图标，展开下拉面板：

**面板头部**

- 标题："What's New"
- 右侧："Mark all as read" 链接（有未读时显示）

**更新列表**

- 每条更新显示：
  - 标题（粗体）
  - 发布日期（如 "Aug 20, 2026"）
  - 摘要（最多显示 2 行，超出截断）
  - 未读标识（左侧蓝色竖条或圆点）
- 列表按发布时间倒序排列
- 最多显示最近 10 条，底部显示 "View all" 链接

**空状态**

- 无更新时显示："No updates yet"

#### 1.3 更新详情弹窗

点击列表中的某条更新，弹出详情弹窗：

**弹窗内容**

- 标题
- 发布日期
- 正文内容（支持富文本：标题、列表、图片、链接等）
- 关闭按钮

**已读标记**

- 打开详情弹窗后，自动标记该条为已读
- 或者：在列表中点击即标记为已读

#### 1.4 "View All" 页面

点击面板底部的 "View all"，进入完整的更新历史页面：

- 显示所有历史更新（分页，每页 20 条）
- 支持按时间范围筛选
- 每条可展开查看详情

---

### 二、管理端 - What's New 管理页面

#### 2.1 入口

- 位置：Settings > What's New Management
- 权限：仅 **System Admin** 角色可见

#### 2.2 管理列表页

**页面布局**

顶部：

- 页面标题："What's New Management"
- **[+ Create New]** 按钮

列表表格：
| 列名 | 说明 |
|------|------|
| Title | 更新标题，可点击编辑 |
| Status | Draft / Published / Scheduled |
| Publish Date | 发布日期（Scheduled 显示计划日期）|
| Created By | 创建人 |
| Views | 已读用户数 / 总用户数 |
| Actions | Edit / Delete |

**筛选与搜索**

- 状态筛选：All / Draft / Published / Scheduled
- 搜索框：按标题搜索

#### 2.3 创建/编辑页面

**基本信息**

- **Title**（必填）：更新标题，最多 100 字符
- **Summary**（必填）：摘要，最多 200 字符，用于列表展示
- **Content**（必填）：正文内容，富文本编辑器

**发布设置**

- **Status**：
  - Draft — 保存草稿，不发布
  - Publish Now — 立即发布
  - Schedule — 定时发布，需选择发布时间

**富文本编辑器功能**

- 标题（H1-H3）
- 粗体、斜体、下划线
- 有序/无序列表
- 链接
- 图片上传（支持拖拽）
- 代码块（可选）

**操作按钮**

- **[Save as Draft]** — 保存为草稿
- **[Publish]** / **[Schedule]** — 根据发布设置显示
- **[Cancel]** — 取消并返回列表

#### 2.4 删除确认

点击删除时弹出确认：

```
Delete this update?

"[更新标题]"

This update has been viewed by 128 users.
Deleting it will remove it from all users' What's New panel.

[Cancel] [Delete]
```

---

### 三、已读状态追踪

#### 3.1 已读规则

- 用户打开详情弹窗后，标记为已读
- 用户点击 "Mark all as read" 后，所有未读标记为已读
- 已读状态与用户绑定，不同用户独立追踪

#### 3.2 管理员视图

管理员在列表页可看到每条更新的阅读统计：

- 格式："128 / 500" （已读用户数 / 活跃用户数）
- 点击数字可查看已读用户列表（可选功能）

## 数据模型

### What's New Item（更新条目）

| 字段             | 类型        | 说明                                 |
| ---------------- | ----------- | ------------------------------------ |
| `id`             | UUID        | 唯一标识                             |
| `title`          | String(100) | 标题                                 |
| `summary`        | String(200) | 摘要                                 |
| `content`        | Text        | 正文内容（HTML）                     |
| `status`         | Enum        | DRAFT / PUBLISHED / SCHEDULED        |
| `publish_date`   | DateTime    | 发布时间                             |
| `scheduled_date` | DateTime    | 计划发布时间（Scheduled 状态时使用） |
| `created_by`     | UUID        | 创建人 ID                            |
| `created_at`     | DateTime    | 创建时间                             |
| `updated_at`     | DateTime    | 更新时间                             |

### What's New Read Status（已读状态）

| 字段      | 类型     | 说明               |
| --------- | -------- | ------------------ |
| `id`      | UUID     | 唯一标识           |
| `item_id` | UUID     | What's New Item ID |
| `user_id` | UUID     | 用户 ID            |
| `read_at` | DateTime | 阅读时间           |

## API 设计

### 用户端 API

#### 获取未读数量

```
GET /api/whats-new/unread-count
Response: { "count": 3 }
```

#### 获取更新列表

```
GET /api/whats-new?page=1&pageSize=10
Response: {
  "items": [
    {
      "id": "uuid",
      "title": "New Feature: Workflow Trigger",
      "summary": "Now you can configure...",
      "publishDate": "2026-08-20T10:00:00Z",
      "isRead": false
    }
  ],
  "total": 25,
  "hasMore": true
}
```

#### 获取更新详情

```
GET /api/whats-new/:id
Response: {
  "id": "uuid",
  "title": "...",
  "summary": "...",
  "content": "<p>...</p>",
  "publishDate": "..."
}
```

#### 标记已读

```
POST /api/whats-new/:id/read
Response: { "success": true }
```

#### 全部标记已读

```
POST /api/whats-new/read-all
Response: { "success": true }
```

### 管理端 API

#### 获取管理列表

```
GET /api/admin/whats-new?status=all&page=1&pageSize=20
Response: {
  "items": [
    {
      "id": "uuid",
      "title": "...",
      "status": "PUBLISHED",
      "publishDate": "...",
      "createdBy": { "id": "uuid", "name": "Admin" },
      "readCount": 128,
      "totalUsers": 500
    }
  ],
  "total": 50
}
```

#### 创建更新

```
POST /api/admin/whats-new
Body: {
  "title": "...",
  "summary": "...",
  "content": "...",
  "status": "PUBLISHED" | "DRAFT" | "SCHEDULED",
  "scheduledDate": "2026-08-25T10:00:00Z" // 仅 SCHEDULED 时需要
}
```

#### 更新

```
PUT /api/admin/whats-new/:id
Body: { ... }
```

#### 删除

```
DELETE /api/admin/whats-new/:id
```

## 风险与注意事项

### 1. 性能考虑

- **风险**：每次页面加载都查询未读数量
- **缓解**：未读数量接口做缓存，用户标记已读时更新缓存

### 2. 富文本安全

- **风险**：XSS 攻击风险
- **缓解**：后端对 HTML 内容做白名单过滤，只允许安全标签

### 3. 图片存储

- **风险**：图片占用存储空间
- **缓解**：限制单张图片大小（如 2MB），总内容大小限制

### 4. 定时发布

- **风险**：调度任务失败导致发布延迟
- **缓解**：使用可靠的任务调度系统，失败时发送告警

## Phase 2 功能详情：按角色/Team 发布

### 一、发布范围配置

在创建/编辑更新时，增加"发布范围"配置项：

**Publish To**

- **All Users**（默认）— 所有用户可见
- **Specific Audiences** — 指定角色或 Team

选择 "Specific Audiences" 后，显示两个多选区域：

```
Publish To:
○ All Users
● Specific Audiences

  Roles:                          Teams:
  ☑ System Admin                  ☑ Sales Team
  ☑ Admin                         ☐ Operations Team
  ☐ Case Owner                    ☐ IT Team
  ☐ Viewer                        ☐ Finance Team
  ...                             ...
```

### 二、配置逻辑

| 配置        | 可见用户                          |
| ----------- | --------------------------------- |
| All Users   | 所有用户                          |
| 仅选角色    | 拥有任一选中角色的用户            |
| 仅选 Team   | 属于任一选中 Team 的用户          |
| 角色 + Team | 满足**任一条件**的用户（OR 逻辑） |

**示例**：选择 "Admin 角色" + "Sales Team"

- Admin 角色的用户可见（不管在哪个 Team）
- Sales Team 的成员可见（不管是什么角色）

### 三、数据模型变化

What's New Item 表增加字段：

| 字段              | 类型 | 说明                                          |
| ----------------- | ---- | --------------------------------------------- |
| `target_audience` | Enum | ALL / SPECIFIC                                |
| `target_roles`    | JSON | 角色 ID 数组，如 `["role-admin"]`             |
| `target_teams`    | JSON | Team ID 数组，如 `["team-sales", "team-ops"]` |

### 四、API 变化

#### 创建/更新时

```json
{
  "title": "...",
  "targetAudience": "SPECIFIC",
  "targetRoles": ["role-admin", "role-case-owner"],
  "targetTeams": ["team-sales"]
}
```

#### 用户端查询时

后端根据当前用户的角色和 Team 过滤：

```sql
WHERE target_audience = 'ALL'
   OR (target_audience = 'SPECIFIC'
       AND (user_role_id IN target_roles
            OR user_team_id IN target_teams))
```

### 五、管理列表显示

管理列表页的 "Publish To" 列显示发布范围：

| Publish To 值 | 显示                          |
| ------------- | ----------------------------- |
| All Users     | "All Users"                   |
| 仅角色        | "Roles: Admin, Case Owner"    |
| 仅 Team       | "Teams: Sales, Ops"           |
| 角色 + Team   | "Roles: Admin · Teams: Sales" |

### 六、阅读统计调整

按角色/Team 发布时，阅读统计的分母变为**目标用户数**：

- All Users：已读 / 总活跃用户
- Specific：已读 / 目标范围内的用户数

## 后续扩展（Future Considerations）

1. **通知推送**：除了被动查看，可选择推送重要更新到用户邮箱
2. **多语言支持**：支持创建不同语言版本的更新内容
3. **更新分类**：支持按类型分类（新功能 / 改进 / Bug修复）
4. **视频支持**：正文支持嵌入视频演示
5. **反馈收集**：用户可对更新内容点赞或评论
